# 规则示例

一条规则同时携带三层，运行时按字段决定它落到哪：

| 字段 | 层 | 强制方式 | 代价 |
|---|---|---|---|
| `denyTools` | **边界** boundary | 工具根本不出现在模型看到的定义里，无从违反 | 零 |
| `requiredFields` | **检查** check | 结果缺字段就退回让它重写，规则原文回给模型 | 一次重写 |
| 正文 | **提醒** reminder | 注入末尾约束块 —— 只是说一声，不是强制 | **每一轮**都花 |

（不用 T1/T2/T3 这种编号：记不住哪个是哪个，而且 T1 听起来像「第一层、最基本的」，
恰恰它最弱 —— 那个误导正好助长了「写一句 prompt 文本就当加了规则」的毛病。）

长正文加一个 `gist:` 索引行，正文改为按需加载（`read_rule`）。
实测一份 18 条的规则集：12k token 正文压成 330 token 索引，36 倍。
**gist 必须带触发条件** —— 模型看到的只有那一行。

两条原则由校验强制，不靠自觉：

1. **提醒必须配检查或边界。** 只有正文的规则会被**拒绝** —— 那等于
   「prompt 里写满禁止但模型照犯」，而且它会出现在规则清单里、看起来系统在管，
   实际什么都没管。**看起来有约束比没有约束更糟。**
2. **能用边界表达的绝不写成提醒。** 边界零成本且不可违反。

用法：把 `.md` 复制到项目根的 `rules/` 下。`nucleus rules` 会列出来。
